## 二、Sprint 规划

### Sprint 1：立刻改变产品感受（1-2 天）

| 维度 | 内容 |
|------|------|
| **目标** | 让用户打开花园时有"这是我的空间"的感觉 |
| **范围** | 背景系统增强（透明度滑块 + 毛玻璃开关 + 2 个新主题） |
| **用户可见变化** | Settings → 背景透明度可拖动。Settings → 主题新增"樱庭"和"雨"。切换主题时背景自动适配合适的透明度 |
| **是否需要改数据库** | 否。localStorage |
| **是否需要新增依赖** | 否 |
| **是否影响现有功能** | 否。纯增量 |

---

### Sprint 2：提升写作体验（2-3 天）

| 维度 | 内容 |
|------|------|
| **目标** | 让编辑器从"功能齐全"到"愿意久坐" |
| **范围** | Link popover（替换 window.prompt）+ Strike 按钮 + 现有编辑器能力打磨（Callout/Divider 优化） |
| **用户可见变化** | 点击 🔗 不再弹出浏览器对话框，而是光标附近浮层。工具栏新增删除线按钮。Callout 支持 Shift+Tab 退出 |
| **是否需要改数据库** | 否 |
| **是否需要新增依赖** | 否（popover 自实现） |
| **是否影响现有功能** | 替换 Link 的 window.prompt 逻辑。其余不变 |

---

### Sprint 3：增强氛围与个性化（2-3 天）

| 维度 | 内容 |
|------|------|
| **目标** | 让花园有"声音"和"时间感" |
| **范围** | BGM 播放器（桌面端，用户主动开启）+ 季节主题自动切换（春樱/夏园/秋暖/冬月） |
| **用户可见变化** | Settings → BGM 开关 + 播放列表。每个季度花园自动更换推荐主题和背景 |
| **是否需要改数据库** | 否。localStorage + 系统时间 |
| **是否需要新增依赖** | 否（HTML5 Audio API） |
| **是否影响现有功能** | 否。BGM 默认关闭 |

## 五、最终建议

### 如果只能先做 3 件事

| # | 做什么 | 为什么是这 3 件 |
|:--:|------|----------------|
| **1** | **背景透明度可调**（Sprint 1） | 5 行 CSS。用户选了一张背景图，但觉得太亮/太暗 → 拖动滑块找到平衡。V1 背景系统的主要缺憾被修复 |
| **2** | **Link popover**（Sprint 2） | 替换 window.prompt。删除当前编辑器最"非花园"的交互。用户写链接时的体验从"1998 年网页"变成"2025 年自然交互" |
| **3** | **4 种完整主题**（Sprint 1） | 花园(已有) + 月夜(已有) + 樱庭 + 雨。4 种主题覆盖用户在不同心境下的需求。主题是视觉身份的最小单元——比任何动画都更能传递"花园感" |

### 为什么不选 BGM

BGM 的情感价值最高，但需要 Sprint 3 的体量（播放器组件 + 曲库管理 + 设置页更新）。先做 Sprint 1+2（合计约 150 行代码），让用户在 2 天内看到 3 个视觉/交互变化。然后从容地做 BGM。

### 为什么不选内部引用 / Wikilink

它是 Phase 7 的事。现在花园只有 50 条测试数据。内部引用在 500 条真实记录后才开始有价值。提前做是过度工程。
