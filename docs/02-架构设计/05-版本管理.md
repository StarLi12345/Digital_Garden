# 版本管理指南

> 写给非程序员。
>
> 你不需要理解 Git，不需要记住命令。
>
> 这份指南告诉你怎么查看、找回和恢复项目的任何历史版本。
>
> ⚠️ **重要提示**：部分早期快照是历史补录，可阅读但不可恢复。
> 详见 [RECOVERY_POLICY.md](RECOVERY_POLICY.md)。

---

## 概念解释

### 两种快照

| 类型 | 图标 | 能恢复吗 | 说明 |
|------|------|---------|------|
| 历史快照 | 📜 | ❌ 不可恢复 | 根据已有文档补录。可以阅读，了解项目历史。 |
| 可恢复快照 | 🔵 | ✅ 可以恢复 | 有独立 Git Commit。可以一键回到这个状态。 |

**如何区分**：打开 [Timeline.md](Timeline.md)，看图标。📜 = 历史，🔵 = 可恢复。

### 什么是"版本"？

每完成一次开发任务，项目就会保存一个"快照"。

快照 = 当时所有文件的完整状态。

就像游戏存档。你可以随时回到任何一个存档点。

### 注意

**2026-05-31 及之前创建的快照都是 📜 历史快照。** 因为那时 Git 仓库还没有建立。

从 `2026-05-31_version-system-complete` 开始，所有新快照都是 🔵 可恢复的。

### 在哪里可以找到快照？

所有快照存放在项目中的 `snapshots/` 目录。

按时间命名，例如：

```
snapshots/
  ├── 2026-05-31_project-birth/      ← 项目诞生
  ├── 2026-05-31_roadmap-design/      ← 路线图设计
  ├── 2026-05-31_architecture-design/  ← 架构设计
  ├── 2026-05-31_mvp-design/          ← MVP 设计
  ├── 2026-05-31_build-rules/         ← 开发规范
  └── 2026-05-31_phase0.1-init/       ← 项目初始化
```

## 如何查看历史版本

### 方式一：查看开发日志

打开 [`docs/CHANGELOG.md`](CHANGELOG.md)。

每一行记录了一次开发活动：
- 什么时间
- 做了什么
- 改了哪些文件

点击快照链接即可查看当时的详细记录。

### 方式二：查看项目时间线

打开 [`docs/Timeline.md`](Timeline.md)。

按时间从早到晚排列，可以看到项目的成长过程。

### 方式三：浏览快照目录

打开 `snapshots/` 目录。

每个子目录就是一个时间节点的存档：
- `snapshot.md` — 当时做了什么
- `metadata.json` — 机器可读的信息

## 如何恢复到某个版本

### 我想到"2026-05-31 MVP 文档设计完成"时的状态

**步骤：**

1. 打开 [`docs/Timeline.md`](Timeline.md)
2. 找到 "2026-05-31 MVP 设计完成" 这一行
3. 点击旁边的快照链接，确认这是你想要的版本
4. 告诉 AI 助手：

> "请恢复到 2026-05-31_mvp-design 这个快照的状态"

AI 助手会帮你完成恢复。

### 我想回到上一个版本

**步骤：**

告诉 AI 助手：

> "请恢复到最近一次快照之前的状态"

## 如何恢复最近一次修改

如果不小心改坏了某个文件：

**步骤：**

告诉 AI 助手：

> "我改坏了 xxx 文件，请从最近的快照中恢复它"

或者：

> "请撤销最后一次修改"

## 如何创建新的快照

正常情况下，你不需要手动创建快照。

每次 AI 助手完成一个开发任务后，会自动：

1. 更新 CHANGELOG.md
2. 创建新的快照
3. 提交 Git 记录

如果你想手动保存当前状态：

告诉 AI 助手：

> "请为当前状态创建一个快照"

---

## 快照包含什么

每个快照目录包含：

| 文件 | 内容 |
|------|------|
| `snapshot.md` | 时间、阶段、完成了什么、改了哪些文件 |
| `metadata.json` | 机器可读的时间、阶段、描述信息 |

## 恢复的安全性

### 救援快照（Rescue Snapshot）

**每次恢复操作之前，系统会自动创建一个"救援快照"。**

救援快照的目的是：如果你后悔了恢复操作，可以立刻回到恢复之前的状态。

就像游戏里的"自动存档"：
- 🎮 你决定读档回到第 3 关
- 💾 系统自动保存当前第 7 关的进度
- 📂 你回到第 3 关
- 🔄 不满意？随时可以加载第 7 关的自动存档

### 救援快照的存放位置

救援快照存放在 `snapshots/` 目录下，使用特殊命名：

```
snapshots/
  └── RESCUE_2026-05-31_103000/
      ├── snapshot.md       ← 记录"这是在恢复前自动保存的"
      └── metadata.json     ← 标记 "rescue_snapshot": true
```

### 恢复的完整流程

当你请求"恢复到某个快照"时：

```
1. 📸 自动创建救援快照（保存当前状态）
2. ⏪ 执行恢复操作
3. ✅ 报告恢复结果
4. ❓ 确认是否满意
```

### 如果后悔了

告诉 AI 助手：

> "请恢复到最近的救援快照"

或者：

> "我不小心恢复错了，请帮我回去"

---

**恢复操作永远不会删东西。它只是切换视角。**

你之前的每一次快照、每一次救援存档，都静静地留在 snapshots/ 目录里。

## 审计引擎

项目提供了自动化的时间一致性检查工具：

```bash
node scripts/audit-engine.mjs        # 检查模式
node scripts/audit-engine.mjs --fix  # 自动修复模式
```

这个工具会：
1. 对比 CHANGELOG 与 Git 历史的时间是否一致
2. 检查每个 Snapshot 的时间是否与对应 Git Commit 匹配
3. 检查是否存在未来时间或倒序时间
4. 发现问题时自动用 Git timestamp 修复

**时间来源规则**：所有时间以 `git log` 的 commit timestamp 为准。AI 不能自行生成时间。

## 常见场景

### "我想看看项目最开始的样子"

1. 打开 Timeline.md
2. 找到最上面的一条记录："项目诞生"
3. 点击快照链接查看

### "今天改了太多，想回到今天早上的状态"

1. 打开 CHANGELOG.md
2. 找到今天最早的一条记录
3. 告诉 AI 助手要恢复到那个快照

### "我不确定该回到哪个版本"

告诉 AI 助手：

> "请帮我列出最近 5 个快照，告诉我每个快照做了什么"
