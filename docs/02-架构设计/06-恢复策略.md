# 恢复策略

> 写给非程序员。
>
> 这份文档回答两个问题：
> 1. 我能回到过去吗？
> 2. 怎么回？

---

## 两种快照

Digital Garden 的快照分为两种：

### 📜 历史快照（Historical Snapshot）

**是什么**：根据已有文档倒推记录的项目历史。

**能做什么**：
- ✅ 阅读当时的开发日志（snapshot.md）
- ✅ 了解当时做了什么决策（conversation.md）
- ✅ 查看时间线（Timeline.md）
- ✅ 理解项目是怎么一步步走到现在的

**不能做什么**：
- ❌ 不能恢复到这个状态
- ❌ 没有对应的 Git Commit

**如何识别**：在 metadata.json 中标记为 `"recoverable": false`

**示例**：

```
snapshots/2026-05-31_project-birth/
  ├── snapshot.md      ← 可阅读
  └── metadata.json    ← "recoverable": false
```

这些快照就像一本历史书——你可以阅读，但不能穿越回去。

---

### 💾 可恢复快照（Recoverable Snapshot）

**是什么**：真实存在、可以一键恢复的项目状态。

**能做什么**：
- ✅ 阅读开发日志
- ✅ 恢复到这个状态（通过 Git）
- ✅ 验证恢复结果
- ✅ 有独立的 Git Commit

**如何识别**：在 metadata.json 中标记为 `"recoverable": true`

**示例**：

```
snapshots/2026-05-31_version-system-complete/
  ├── snapshot.md      ← 可阅读
  ├── metadata.json    ← "recoverable": true
  └── conversation.md  ← 了解当时为什么做这个决定
```

这些快照就像游戏里的存档点——你可以随时加载。

## 如何恢复

### 回到一个可恢复快照

**步骤**：

1. 打开 [Timeline.md](Timeline.md)
2. 找到目标快照，确认它标记了 🔵（可恢复）
3. 告诉 AI 助手：

> "请恢复到快照 2026-06-01_xxx"

4. AI 助手会：
   - 📸 自动创建救援快照（保存当前状态）
   - ⏪ 执行恢复
   - ✅ 验证恢复结果
   - 📋 报告完成

5. 如果不满意：告诉 AI "恢复到最近的救援快照"

---

### 回到一个历史快照

历史快照不能直接恢复（因为没有对应的 Git Commit）。

但你可以：

1. 阅读 snapshot.md 和 conversation.md，了解那个时间点做了什么
2. 告诉 AI："请参考 2026-05-31_architecture-design 快照的内容，帮我理解当时的架构决策"
3. 如果需要手动重建当时的文件状态，AI 可以根据快照记录来辅助

---

## 如何验证一个快照是否可恢复

### 方式一：看 Timeline

[Timeline.md](Timeline.md) 中，每个快照都标注了类型：

- 📜 = 历史快照（不可恢复）
- 🔵 = 可恢复快照

### 方式二：看 metadata.json

打开对应快照的 `metadata.json`：

```json
{
  "recoverable": false   ← false = 不可恢复
}
```

```json
{
  "recoverable": true    ← true = 可以恢复
}
```

### 方式三：问 AI

> "快照 xxx 可以恢复吗？"

## 救援快照（Rescue Snapshot）

### 是什么

每次执行恢复操作时，系统会自动保存当前的完整状态。

### 为什么需要

如果你恢复到一个旧版本后反悔了，救援快照让你可以回到恢复前的状态。

就像游戏里读档前的自动存档。

### 如何回到救援快照

> "请恢复到最近的救援快照"

### 救援快照存放位置

```
snapshots/
  └── RESCUE_YYYY-MM-DD_HHMMSS/
      ├── snapshot.md
      └── metadata.json    ← "type": "rescue_snapshot"
```

## 快照目录完整结构

```
snapshots/
  └── YYYY-MM-DD_名称/
      ├── snapshot.md       ← 完成了什么
      ├── metadata.json     ← 机器可读的元数据
      └── conversation.md   ← 为什么做这个决定
```

三个文件分别回答三个问题：

| 文件 | 回答的问题 |
|------|-----------|
| snapshot.md | 做了什么？ |
| conversation.md | 为什么这么做？ |
| metadata.json | 什么时候？谁？能恢复吗？ |

## 常见问题

### Q: 为什么有些快照不能恢复？

A: 它们是在建立 Git 仓库之前的历史。项目通过已有文档倒推了这些记录，但它们没有独立的 Git Commit。

### Q: 历史快照有价值吗？

A: 非常有价值。它们记录了项目是怎么一步步思考和决策的。即使不能恢复，理解"当时为什么这么选"对未来的决策很重要。

### Q: 从现在开始，每个快照都可恢复吗？

A: 是的。从快照 `2026-05-31_version-system-complete` 开始，每个快照都有独立的 Git Commit，都可以恢复。

### Q: 如果我不小心删了快照文件夹怎么办？

A: 快照文件和 Git Commit —— 一对应。即使删了快照文件夹，Git 历史仍然保留着当时的完整代码。快照文件本身也在 Git 中，可以通过 Git 找回来。

| 验证快照可恢复性 | "检查快照 xxx 是否可恢复" |
