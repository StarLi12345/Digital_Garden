# Visual Identity Review 01 — Product Personality Sprint

> 不是"还能做什么功能"。是"这个产品最终应该长什么样"。
>
> 审查日期：2026-05-31
> 当前阶段：功能层基本完备，进入视觉身份定义阶段

---

## 第一部分：产品人格分析

### 1. 当前产品已经形成的人格

**温暖花园（Warm Garden）。**

证据来自当前已实现的设计决策：

- 配色：奶油色背景 + 花园绿主色 + 陶土色点缀
- 文案：没有"提交""确认""取消"。只有"种下种子""来自花园""写点什么"
- 排版：圆角、留白、呼吸感、无密集信息
- 动效：轻淡入 250ms, 无弹跳, 无炫技
- 时间表达："5个月前""三周前"——不是绝对日期

这不是设计层拍板的。是 6 个 Phase 的产品决策自然积累而成的默认人格。

### 2. 用户实际感知到的人格

基于当前 UI 和文案，陌生用户打开后感知到的：

> "一个温暖、安静、好看的日记应用。有点日式小清新。"

Product Checkpoint 01 已确认：用户 30 秒内不会意识到这是"Digital Garden"——他们会认为这是"好看的私人日记"。说明花园的视觉人格已经形成，但产品独特性仍在表达中。

### 3. 用户（你）希望感知到的人格

基于 resource 库和项目文档：

**二次元陪伴 + 时间档案馆的混合体。**

```
温暖花园 ──────────────── 时间档案馆
     │                        │
     │   ┌──────────────┐     │
     │   │ 二次元陪伴感  │     │
     │   └──────────────┘     │
     │                        │
   现在                    未来需要
```

你的资源库（168 张插图、57 首音乐）说明你希望花园有"二次元陪伴感"——它不只是工具，是有生命的。但你需要的是"克制的二次元"——不是萌系 UI、不是看板娘、不是 Live2D。是意境——像吉卜力、像《虫师》、像东方 Project 的设定集。美，但不幼。

同时，项目愿景（"多年后看到过去的自己"）要求花园也有"时间档案馆"的深度——不止是温暖，还有重量。

### 4. 三者是否一致

**当前一致，但未来需要分化。**

- 产品人格（温暖花园）✅ 已传达
- 用户感知（好看的日记）⚠️ 正确但不完整——缺少"时间深度"的感知
- 用户希望（二次元陪伴 + 时间档案馆）⚠️ 产品还不具备

**差距**：产品现在给人的感觉是"轻柔的日记本"，但用户希望它最终是"有生命的、有深度的时间容器"。

## 第二部分：主题系统设计评审

### Theme A：花园（当前主题）— 保留并作为默认

**核心关键词**：温暖 · 安静 · 生长 · 自然

**配色**（当前）：
- 背景：暖奶油色（#faf8f5）/ 深棕（#1e1c19）
- 主色：花园绿（#6b8c5c / #8aab7a）
- 点缀：陶土色（#d4956a / #e0a87c）

**情绪价值**：舒适、安全、缓慢、日常陪伴。适合每天打开的默认体验。

**是否适合作为默认主题**：✅ 是。这是产品最自然的面貌。

---

### Theme B：时间档案馆 / 月夜花园（Moonlit Archive）

**核心关键词**：记忆 · 时间 · 痕迹 · 深沉

**配色建议**：
- Light: 深蓝灰背景（#1a1d23）字体灰白 + 琥珀色点缀（#c9a96e）
- Dark: 纯黑背景（#0d0d0f）字体月光白 + 金色点缀（#e8d5a3）

**字体风格**：当前 Geist Sans 保持。可考虑增加字间距 0.02em（增强"时间感"）。

**情绪价值**：沉思、怀旧、夜晚。适合深夜打开花园回顾旧记录。

**适合哪些用户**：喜欢 Obsidian 暗色风格但觉得它太冷的用户。适合在深夜记录情绪、梦境。

**是否值得开发**：✅ 值得，但不是紧急。这是差异化主题——它让花园在"温暖"之外还有"深邃"的一面。这对"时间档案馆"愿景很重要。

---

### Theme C：二次元陪伴 / 樱庭（Sakura Garden）

**核心关键词**：温柔 · 陪伴 · 季节 · 日系

**配色建议**：
- Light: 淡粉背景（#fdf6f8）樱花粉主色（#d4899a）淡紫点缀（#b8a9c9）
- Dark: 深紫灰背景（#1d1a20）柔粉主色（#e8a0b0）金色点缀

**情绪价值**：柔软、甜蜜、被陪伴。适合那些"今天只想被温柔对待"的日子。

**是否会破坏 Digital Garden 的沉浸感**：有风险。如果樱庭主题做得太"萌"——粉嫩、圆角过大、装饰性元素过多——它会削弱花园的"成年人私人空间"定位。如果做得像《虫师》/《夏目友人帐》那种"日式淡雅"——则是可接受的。

**是否应该作为独立主题**：✅ 是，但必须克制。关键约束：
- 不使用动漫角色插画作为 UI 元素
- 不使用萌系字体（保持 Geist Sans）
- 不使用装饰性边框（樱花花纹、和风图案）
- 仅通过配色传达日系感

---

### 推荐方案

| 决策 | 内容 |
|------|------|
| **保留主题数** | 3 个（花园 / 月夜 / 樱庭） |
| **默认主题** | 花园（当前） |
| **优先开发** | 月夜花园（Theme B） |

**为什么月夜优先于樱庭**：

月夜花园直接服务于"时间档案馆"愿景——它让花园的"时间深度"有了视觉表达。而樱庭主要服务于"二次元陪伴感"——这个需求可以靠配色和资源库的图片来满足，不需要独立主题。

## 第三部分：资源库审查

### 资源库概况

| 类别 | 数量 | 内容特征 |
|------|:--:|------|
| 图片 | 168 | Pixiv 插图、东方 Project、三体、截图、摄影 |

### 能力评估（用户价值 ÷ 开发成本）

| # | 能力 | 用户价值 | 开发成本 | 评分 | 建议 |
|:--:|------|:--:|:--:|:--:|------|

| 2 | **页面切换动画** | ⭐⭐⭐ | ⭐ 极低 | ⭐⭐⭐ | ✅ 已做（Framer Motion） |
| 3 | **BGM** | ⭐⭐⭐⭐ | ⭐⭐ 低 | ⭐⭐ | ⚠️ 有价值但需谨慎 |
| 4 | **季节主题资源** | ⭐⭐⭐ | ⭐⭐ 低 | ⭐⭐ | ⚠️ 值得规划 |
| 5 | **动态粒子** | ⭐⭐ | ⭐⭐⭐ 中 | ⭐ | ❌ 当前不做 |
| 6 | **视频背景** | ⭐ | ⭐⭐⭐⭐ 高 | 极低 | ❌ 不做 |
| 7 | **Live2D** | ⭐⭐ | ⭐⭐⭐⭐⭐ 极高 | 极低 | ❌ 永久不做 |
| 8 | **鼠标跟随特效** | ⭐ | ⭐⭐ 低 | 极低 | ❌ 不做 |

### 详细分析

**静态背景图**（优先）：
- 用户价值：高。一张高质量的背景图可以瞬间改变花园的氛围——从"白色空白"变成"有空间感的花园"
- 开发成本：极低。CSS `background-image` 一行
- 资源库匹配：168 张图片中有大量适合做背景的插图（风景、夜景、樱庭）
- 建议：允许用户从资源库中选择背景图，或让花园自动轮换

**BGM**：
- 用户价值：高。音乐是最强的情感载体——比颜色和字体更直接
- 开发成本：低。HTML5 Audio API，一个播放器组件
- 风险：自动播放被浏览器禁止（需要用户点击触发），多设备静音策略复杂
- 资源库匹配：57 首音乐，以钢琴编曲为主，风格适合花园
- 建议：见第四部分专项分析

**动态粒子**（当前不做）：
- 虽然资源库没有粒子素材，但前端粒子库（particles.js）可以实现
- 但粒子的气质与"安静的花园"冲突——粒子是炫技，不是陪伴
- ANIMATION_GUIDE.md 已明确禁止

**Live2D / 视频背景**（永久不做）：
- Live2D 需要模型、渲染引擎、交互系统——这是另一个项目的体量
- 视频背景分散注意力、消耗性能、与安静气质冲突
- ANIMATION_GUIDE.md 已明确禁止

## 第四部分：背景音乐专项评审

### Digital Garden 是否应该有背景音乐

**应该有。但必须是用户主动选择的，不是强制播放的。**

### 方案分析

| 方案 | 描述 | 用户体验 | 风险 |
|------|------|---------|------|
| A. 全局自动播放 | 打开花园就开始播放 | 侵入感强 | 🔴 浏览器禁止 autoplay，用户反感 |
| B. 用户主动开启 | 设置中开启 BGM，可切换曲目 | 尊重用户选择 | 🟢 无 |
| C. 每主题绑定 BGM | 切换主题自动换曲 | 沉浸感好但复杂 | 🟡 需要曲库管理 |
| D. 完全不做 | 无 BGM | 无风险 | 🟢 但浪费了 57 首音乐的价值 |

### 推荐方案：B + 未来 C

**Phase 1（当前可做）**：用户主动开启模式

- 在 Settings 页添加 BGM 开关（默认关闭）
- 用户开启 → 从资源库随机播放
- 可上一首/下一首
- 音量控制
- 关闭页面时自动停止

**Phase 2（主题系统完成后）**：

- 每个主题绑定一个默认播放列表
- 花园主题 → 钢琴编曲 / 轻音乐
- 月夜主题 → 氛围 / 古典
- 樱庭主题 → 日系 / 温柔

### 多设备场景

- 每次打开花园时需要重新点击"播放"（浏览器限制，无法绕过）
- 不同标签页之间不共享播放状态（这是正确的——用户可能在多个标签页同时打开花园）

### 手机端影响

- 移动端 BGM 更敏感——用户在公共场合
- 建议手机端默认为"静默模式"，不显示 BGM 控件
- 仅桌面端支持 BGM

### 长时间使用影响

- 如果用户连续写作 30 分钟，同一首BGM 循环或播放列表过短会产生疲劳
- 建议最少播放列表长度：10 首（~40 分钟不重复）
- 用户当前有 57 首音乐——远超最低要求

## 第六部分：Visual Sprint Roadmap

### V1 — 主题系统 + 静态背景（Now）

**内容**：
- 新增月夜花园主题（Theme B：深色 + 琥珀点缀）
- 新增樱庭主题（Theme C：克制日系粉）
- 静态背景图支持（从 resource/picture 中选择，CSS background-image）

**为什么先做这个**：主题和背景是视觉身份的基础。它们让花园从"一个好看的 UI"变成"一个有个性的空间"。

**开发成本**：新增 2 个 CSS 变量组 + 1 个背景选择组件。~100 行 CSS + ~50 行组件。

---

### V2 — BGM 系统（Next）

**内容**：
- 桌面端 BGM 播放器
- 从 resource/music 读取曲目
- 播放/暂停/上一首/下一首/音量
- 设置页 BGM 开关

**为什么 V2 而不是 V1**：BGM 依赖 Settings 页和主题系统。主题先就位，BGM 才能绑定主题播放列表。

---

### V3 — 季节主题（Later）

**内容**：
- 根据当前月份自动切换主题变体

- 秋季（9-11月）：温暖花园（更暖色调）

**为什么 V3**：季节主题的价值在"时间感"——但这需要主题系统（V1）完整后才能实现。

## 最终问题：如果只能做一个视觉升级

**让用户可以选择一张背景图。**

不是新主题。不是 BGM。不是动画。

是一张背景图。

因为：

1. **一张图改变整个空间的氛围。** 白色背景是"工具"。一张图片背景是"属于我的地方"。

2. **资源库已经准备好了。** 168 张图片，不需要新素材。

3. **用户不需要学习。** 选择图片 → 预览 → 确定。3 步。比切换主题更直观。

4. **它不打扰任何人。** BGM 需要用户主动播放（浏览器限制）。背景图不发出声音、不动、不炫——它只是在那里，安静地改变氛围。

5. **它是最接近"推开自己的房门"的体验。** 每次打开花园，看到自己选的背景图——这是你的空间，不是别人的 App。

**数字花园的终极视觉升级，不是更炫，而是更像"家"。**

---

> **Visual Identity Sprint 的第一步**：让用户把自己的图片放进花园。不是给花园更多功能——是给花园更多人格。
