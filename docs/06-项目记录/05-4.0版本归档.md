## 一、4.0 定位

如果说 3.0 是"把已有的做好"——编辑器、视觉系统、多用户、AI 对话收尾闭环——那么 **4.0 就是"开门迎客"**。核心命题是：

> **从一个需要登录才能看的花园，变成一个任何人都可以逛的公开花园。**

同时补上了 3.0 最薄弱的一环：**生产环境部署**。Docker 化、健康检查、一键部署、RSS 分发、数据库备份——让这个花园不仅能看，还能稳。

## 二、3.0 → 4.0 全域对比

### 2.1 访问模型（最大变化）

| 维度 | 3.0 | 4.0 |
|------|-----|-----|
| 未登录访客 | 强制跳转 `/login` | **自动以 Star.Li 身份浏览公开内容** |
| 鉴权机制 | 单一 `garden-session` cookie | **双 cookie 分离**：`garden-session`（身份）+ `garden-auth: verified`（写权限） |
| 写操作保护 | `getUserId()` | **`requireAuth()`** — 必须 `garden-auth=verified` |
| 公开/私密 | 仅 `Entry.isPrivate` | **`User.visibility` + `Entry.isPrivate`**，双层可见性 |
| 账号切换 | `/api/auth/switch` | 已保留，管理员可在多个身份间切换 |
| 中间件 | `src/middleware.ts` — 鉴权重定向 | **完全重写** — 自动创建访客 session |

**设计理念**：
```
未登录 → 自动成为 Star.Li（只读）
已登录 Star.Li → 展示账号自己的内容
已登录私密账号 → 公开 + 私密笔记
```

这是 4.0 最根本的架构决策，影响了 6 个 API 路由、3 个 server action、中间件和前端 Nav 组件。

## 三、新增功能详解

### 3.1 访客模式（Guest Auto-Login）

**影响文件**：`src/middleware.ts`

```typescript
// 4.0 中间件逻辑
if (!session || !session.value) {
  // 自动以 Star.Li 身份创建访客 session
  response.cookies.set("garden-session", "default-user", { httpOnly: true, ... });
  response.cookies.set("garden-user-id", "default-user", { httpOnly: false, ... });
  // 注意：不设置 garden-auth，标记为访客
}
```

**权限分级**：

| Cookie | 来源 | 能做什么 |
|--------|------|---------|
| 无 `garden-auth` | 中间件自动 | 浏览公开笔记、搜索、图谱 |
| `garden-auth=verified` | 登录后 | 写笔记、编辑、删除、管理账号 |

开发服务器（`next dev`）的 Turbopack/HMR 在非 localhost 访问时 JS 不执行。手机测试必须用生产模式：

```bash
npx next build                      # 构建
npx next start -p 3000 -H 0.0.0.0  # 启动（监听所有网口）
```

手机访问 `http://<电脑IP>:3000`，同 WiFi 下即可测试。

### 3.10 Cookie 安全修复

原来的 `secure: process.env.NODE_ENV === "production"` 导致生产模式 HTTP 下 cookie 被拒（手机本地测试不可用）。改为 `secure: request.url.startsWith("https://")` — 只有真正 HTTPS 时才加 Secure 标志。

| 文件 | 作用 |
|------|------|

| `.dockerignore` | 排除 node_modules/.next/resource 等 |

| 文件 | 方式 |
