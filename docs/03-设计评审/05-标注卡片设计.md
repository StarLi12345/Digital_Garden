# Callout UX Review — 花园便签

> 编码前的最后一步：明确"花园便签"的体验定义。

---

## 一、花园便签与 Blockquote 的本质区别

现在的 Blockquote：
```
┌──────────────────────────────┐
│ │  "这是别人说过的话。"        │
│ │  斜体 · muted 灰色 · border │
└──────────────────────────────┘
```
语义：「这是我从别处引用的。」

花园便签：
```
┌──┬───────────────────────────┐
│🌱│ 那天雨很大。               │
│  │ 但我记得很清楚——           │
│  │ 这是我自己说的话。         │
│  │ 正体 · foreground · accent │
└──┴───────────────────────────┘
```
语义：「这是我自己说的，并且想让未来的自己再看到。」

| 维度 | Blockquote | Callout |
|------|-----------|---------|
| **谁的话** | 别人的 —— "引用" | 自己的 —— "珍藏" |
| **语气** | 转述 | 强调 |
| **斜体** | 是 —— 表示"非我" | 否 —— 表示"正是我" |
| **文字颜色** | muted — 次要信息 | foreground — 重要信息 |
| **边框颜色** | border — 中性 | accent — 温暖 |
| **背景** | 无 | 极淡暖色 |
| **花园隐喻** | 路牌（指向别处） | 便签（贴在自己花园里） |
| **按钮** | ❝ | 🌱 |

**一句话区分**：Blockquote 说"听听这个"；Callout 说"记住这个"。

## 二、便签适合承载什么内容

### ✅ 应该放进便签的

| 内容类型 | 示例 |
|---------|------|
| **情绪的高点** | "那一刻我突然理解了什么是孤独。" |
| **回忆的核心画面** | "她推开门，阳光从背后照进来。" |
| **想法中的顿悟** | "也许问题不在于时间不够，而在于我不想做。" |
| **学习中记住的一句话** | "The best time to plant a tree was 20 years ago." |
| **梦境中最清晰的片段** | "我在飞。不是害怕，是自由。" |
| **自我对话** | "写到这里，我突然问自己：你真的想要这个吗？" |

### ❌ 不应该放进便签的

| 内容类型 | 为什么不适合 |
|---------|------------|
| **整段长篇** | 如果 5 段都是便签，就没有便签了。便签是稀有物——一条记录中 0-2 个 |
| **事实性陈述** | "今天去了超市"——这不值得标记。便签标记的是情感，不是事件 |
| **外部引用** | 那是 Blockquote 的职责。便签是"自己的话" |
| **代码/技术内容** | 代码块已经存在 |

### 设计约束

**不提供"便签类型"切换。** Notion 的 Callout 有信息/警告/成功/错误四种颜色。花园便签只有一种——因为花园不是在传递"信息级别"，而是在说"这段话对我很重要"。重要不需要分类。

## 三、是否同步纳入 Divider

**建议：是。E3 的 Divider 部分与 Callout 捆绑交付。**

理由：

1. **Divider 是 StarterKit 自带的**。暴露它只需要在 TOOLBAR_BUTTONS 数组加 1 行 `{ label: "—", title: "分割线", action: "horizontalRule", group: "block" }`。2 行代码。

2. **Callout 和 Divider 都是"优化内容层次"的工具。** Callout 标记"重要的段落"，Divider 标记"话题的边界"。它们服务于同一个编辑需求——让长文本更有结构。

3. **Strike 暂不捆绑。** Strike（删除线）虽然在 StarterKit 中，但它改变的是行内语义（"我否定过这个想法"），与 Callout/Divider 的块级层次不同。单独评估。

**是否捆绑 Strike**：否。Callout + Divider 一次提交。Strike 后续单独评估。

## 四、编辑态与阅读态的视觉表现

### 编辑态（TipTap Editor）

用户正在 /plant 或编辑模式中写作。

```
┌────────────────────────────────────────┐
│ [H2] [H3] [B] [I] [•] [1.] [</>]     │  ← 工具栏
│       [❝] [🌱] [—]                    │  ← 🆕 Callout + Divider
├────────────────────────────────────────┤
│                                        │
│  今天去了东京。                         │  ← 普通段落
│                                        │
│  ┌──┬─────────────────────────────┐    │
│  │🌱│ 但最让我印象深刻的不是东京塔。 │    │  ← 花园便签
│  │  │ 是便利店门口躲雨时，          │    │     编辑态与阅读态视觉一致
│  │  │ 旁边老奶奶递过来的一把伞。    │    │
│  └──┴─────────────────────────────┘    │
│                                        │
│  —————————————————————————————         │  ← 分割线
│                                        │
│  后来我一直在想这件事。                 │  ← 普通段落
│                                        │
└────────────────────────────────────────┘
```

**编辑态行为**：
- 点击 `🌱` 按钮 → 当前位置插入一个 Callout 块（基于 Blockquote + custom attrs）
- 在 Callout 内按 Enter → 在 Callout 内创建新段落（不是退出 Callout）
- 在 Callout 内按 Backspace（空白时）→ 退出 Callout，回到普通段落
- 点击 `—` 按钮 → 当前位置插入分割线

### 阅读态（EntryRenderer / 详情页）

```
│  │  │ 是便利店门口躲雨时，          │    │     编辑态所见即所得
│  │  │ 旁边老奶奶递过来的一把伞。    │    │

│                                        │

│                                        │

│                                        │

```

### 阅读态 CSS 关键问题

当前 EntryRenderer 使用 TipTap 的 `generateHTML()` 生成 HTML。如果 Callout 是 `blockquote` 节点 + 自定义属性，`generateHTML` 输出的 HTML 需要能被 prose CSS 选中。

**两种方案**：

| 方案 | 实现 | 风险 |
|------|------|------|
| A | 自定义 TipTap Node extension（独立节点类型 `<callout>`） | 需要自定义 extension + generateHTML 支持。复杂但语义正确 |
| B | 复用 Blockquote + CSS class（`<blockquote class="callout">`） | generateHTML 可能不保留自定义 class。需要验证 |

**推荐方案 A 的简化版**：

不创建完整自定义节点。而是：
1. 编辑态：使用 Blockquote + 自定义 CSS（Tailwind 直接对 `.ProseMirror blockquote[data-callout]` 应用样式）
2. 阅读态：在 Markdown 中表示为 `> 🌱 内容`（带前缀的 blockquote），或者更简单——直接用 `<blockquote class="callout">`

**最终技术支持由编码时验证。** UX 层面的要求是：**编辑时看到的 Callout 样式，必须与阅读时一致。**

| 编辑态视觉 | 阅读态视觉 | 对齐？ |
|-----------|-----------|:--:|
| 暖色背景 | 暖色背景 | 必须一致 |
| accent 左边框 | accent 左边框 | 必须一致 |
| 正体文字 | 正体文字 | 必须一致 |
| 🌱 前缀（可选） | 🌱 前缀（可选） | 必须一致 |

## 五、Divider UX

Divider 是纯粹的视觉分隔符。无交互，无内容。

**编辑态**：`<hr>` — 灰色细线。

**阅读态**：`<hr>` — 同样的灰色细线。prose 样式自带。

**工具栏**：`—` 按钮。放在 Callout 旁边（同属 `block` 组）。

**行为**：点击 → 在当前位置下方插入 `<hr>` → 光标移到 `<hr>` 下方的新段落。

## 六、结论

| 决策 | 结论 |
|------|------|
| Callout vs Blockquote | Callout 是"记住这个"，Blockquote 是"听听这个"。语义不同 |
| 便签适应什么内容 | 情绪高点、回忆画面、顿悟、自我对话。稀有使用——一条 0-2 个 |
| 是否捆绑 Divider | ✅ 是。2 行代码。同属"块级层次"编辑需求 |
| 是否捆绑 Strike | ❌ 否。行内语义，后续单独评估 |
| 编辑态 vs 阅读态 | 视觉必须一致。技术创新细节由编码时验证 |
| 便签类型 | 不提供类型切换。只有一种温暖的 accent 配色 |
