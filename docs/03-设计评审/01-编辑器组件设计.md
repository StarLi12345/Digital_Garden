## 三、技术方案

### 3.1 TipTap Extension 选择

#### 推荐方案：`@tiptap/starter-kit`

**新增依赖**：2 个

| 包 | 版本 | 用途 | 大小（gzipped） |
|----|------|------|:--:|
| `@tiptap/react` | latest | React 集成组件 | ~15KB |
| `@tiptap/starter-kit` | latest | 基础扩展集合 | ~30KB |

**starter-kit 包含的扩展**：

| 扩展 | MVP 需要 | 处理方式 |
|------|:--:|------|
| Document | ✅ | 保留 |
| Paragraph | ✅ | 保留 |
| Text | ✅ | 保留 |
| Heading | ✅ | 保留，**配置 levels: [2, 3]**（仅 H2/H3） |
| Bold | ✅ | 保留 |
| Italic | ✅ | 保留 |
| Strike | ❌ | starter-kit 自带，工具栏不暴露按钮即可 |
| Code | ❌ | starter-kit 自带，工具栏不暴露 |
| CodeBlock | ❌ | starter-kit 自带，工具栏不暴露 |
| BulletList | ✅ | 保留 |
| OrderedList | ✅ | 保留 |
| ListItem | ✅ | 保留 |
| Blockquote | ✅ | 保留 |
| HorizontalRule | ✅ | 保留 |
| HardBreak | ✅ | 保留（Shift+Enter 换行） |
| History | ✅ | 保留（Undo/Redo） |
| Gapcursor | ❌ | starter-kit 自带，不暴露 |

**选择 starter-kit 而非单独安装扩展的理由**：
1. 单个包管理版本，减少依赖碎片
2. 多出的扩展（Code/Strike/Gapcursor）不占工具栏按钮，不影响用户
3. 如果单独安装 10 个扩展，未来版本升级需要逐个检查兼容性

#### 备选方案：单独安装扩展

```json
"@tiptap/core": "latest",
"@tiptap/react": "latest",
"@tiptap/extension-document": "latest",
"@tiptap/extension-paragraph": "latest",
"@tiptap/extension-text": "latest",
"@tiptap/extension-heading": "latest",
"@tiptap/extension-bold": "latest",
"@tiptap/extension-italic": "latest",
"@tiptap/extension-bullet-list": "latest",
"@tiptap/extension-ordered-list": "latest",
"@tiptap/extension-blockquote": "latest",
"@tiptap/extension-horizontal-rule": "latest",
"@tiptap/extension-history": "latest"
```

**优点**：依赖更少（只包含需要的）
**缺点**：13 个包 vs 2 个包，版本管理更复杂

**最终建议**：推荐方案（starter-kit）。2 个包够简洁。

### 3.2 数据存储方案

#### 编辑器内部状态

```
编辑器（TipTap）
  └── editor.getJSON()  →  TipTap JSON 对象
       │
       ├── 用于 content 字段存储
       └── 用于编辑器的 content 恢复
```

#### 保存流程

```
用户点击"保存"
  │
  ├── 1. 从编辑器获取 JSON:     editor.getJSON()
  ├── 2. 序列化为字符串:          JSON.stringify(json)
  ├── 3. 转换为 Markdown:        jsonToMarkdown(json)
  │       └── 由 src/lib/markdown.ts 中的转换函数处理
  ├── 4. 调用 P1.1 Server Action:
  │       createEntry({
  │         content:    JSON.stringify(json),  ← TipTap JSON
  │         contentMd:  markdown,              ← 转换后的 Markdown
  │         title, type, tags...
  │       })
  └── 5. 数据库写入双字段
```

#### 加载流程（编辑模式）

```
从数据库获取 Entry
  │
  ├── entry.content     →  JSON.parse() →  TipTap JSON → editor.commands.setContent(json)
  └── entry.contentMd   →  不用于编辑器恢复（JSON 更精确）
```

#### 为什么这样设计

| 问题 | 回答 |
|------|------|
| 为什么编辑器用 JSON 恢复而不是 Markdown？ | JSON 精确还原格式。Markdown 解析存在歧义（如 `**粗体**` 被当成文本还是格式？） |
| 为什么保存时要生成 Markdown？ | 架构硬约束（Decision D-005）。搜索和导出依赖 contentMd。 |
| 转换函数放在哪里？ | `src/lib/markdown.ts` — 独立函数，不依赖 TipTap 运行时 |

### 3.3 与 P1.1 的衔接方案

P1.1 的 Server Actions 签名已确定，P1.2 无需修改 P1.1 代码：

```typescript
// P1.1 提供的接口（已实现，无需修改）
createEntry({
  title:      string,   // ← 来自 TitleInput（P1.3）
  type:       string,   // ← 来自 TypeSelector（P1.3）
  content:    string,   // ← JSON.stringify(editor.getJSON()) ← P1.2
  contentMd:  string,   // ← jsonToMarkdown(editor.getJSON())  ← P1.2
  tags:       string[], // ← 来自 TagInput（P1.3）
})

// 编辑流程同理
updateEntry(slug, {
  title:      string,   // ← 来自 TitleInput
  type:       string,   // ← 来自 TypeSelector
  content:    string,   // ← 编辑器 JSON
  contentMd:  string,   // ← 编辑器 JSON → Markdown
  tags:       string[], // ← 来自 TagInput
})
```

**衔接点总结**：
- P1.2 只负责编辑器组件和 JSON↔Markdown 转换
- P1.2 不直接调用 Server Actions（由 P1.3/P1.4 负责集成）
- P1.2 通过 props 回调向父组件暴露编辑器内容和状态

### 4.3 如何保持 Digital Garden 设计风格

**温暖**：
- 编辑器背景使用 `bg-card`（奶油白），不是纯白
- 工具栏按钮 hover 使用 `bg-muted`（温暖灰色）
- 光标颜色使用 `--color-primary`（花园绿）

**安静**：
- 工具栏分隔符使用 `--color-border`，淡到几乎看不见
- 空状态文字使用 `--color-muted-foreground`
- 无闪烁动画，所有交互使用 `.interactive` 类（150ms transition）

**舒适**：
- 编辑区域最小高度 300px，留足呼吸空间
- 行高 1.75，段落间距 1em
- Focus 时无刺眼的蓝色 ring，使用 `--color-ring`（半透明花园绿）
- 字体使用 Geist Sans（已在 Layout 中配置），字号 15px

**不做什么**：
- 不使用 neon/荧光色
- 不使用粗边框
- 不模仿 Google Docs / Notion 的密集工具栏
- 不在编辑器中插入 emoji 装饰

## 五、风险分析

### 5.1 SSR / Hydration

| 风险 | 说明 | 解决方案 |
|------|------|---------|
| TipTap 需要浏览器 DOM | 服务端渲染时会报错 `document is not defined` | 使用 `next/dynamic` 动态导入，`ssr: false` |
| Hydration mismatch | 编辑器内容在服务端和客户端不一致 | 编辑器作为 Client Component，不参与 SSR |
| 编辑器加载闪烁 | 动态导入时编辑器区域短暂为空 | 显示骨架屏（Skeleton）占位，高度 300px |

**推荐方案**：

```typescript
// src/app/plant/page.tsx (P1.4)
const Editor = dynamic(() => import("@/components/editor/editor"), {
  ssr: false,
  loading: () => <EditorSkeleton />,
});
```

### 5.2 中文输入法

| 风险 | 说明 | 解决方案 |
|------|------|---------|
| 拼音输入时字符重复 | 某些 IME 下 ProseMirror 的 input 事件处理时序问题 | TipTap 基于 ProseMirror，**已知对中文 IME 有良好支持**。使用官方 `@tiptap/react` 封装即可，不自定义 input 处理 |
| 组合输入（composition） | IME 的 compositionstart / compositionend 事件 | TipTap 内部已处理。开发者**不需要**手动监听这些事件 |
| macOS 自带中文输入法 | macOS 的中文输入法有时行为特殊 | 在开发中测试 macOS 自带拼音输入法，确认无问题再验收 |

**缓解策略**：
- 不做任何自定义 input 事件处理
- 不使用 `editor.commands.insertContent()` 在 composition 期间插入内容
- 验收时在 macOS 中文输入法下连续输入 2 分钟不出现重复字符

### 5.3 Markdown 转换

| 风险 | 说明 | 解决方案 |
|------|------|---------|
| 转换不完整 | 自写的 `jsonToMarkdown` 可能遗漏边缘情况 | 只支持 P1.2 的 7 种节点类型。对其他节点降级为纯文本 |
| 嵌套格式 | `**粗体中的*斜体***` 需要正确处理 | 递归遍历 JSON 树，对每个 inline mark 包裹对应语法 |
| 空文档 | 新建条目时编辑器内容为空 | 空 JSON 返回空字符串，contentMd 为 `""` |

**转换范围（P1.2）**：

```
✅ 支持的节点：
   doc → 遍历子节点
   paragraph → text + \n\n
   heading (h2) → ## text\n\n
   heading (h3) → ### text\n\n
   bulletList → - item\n
   orderedList → 1. item\n
   blockquote → > text\n
   horizontalRule → ---\n\n

✅ 支持的 Mark：
   bold → **text**
   italic → *text*
   strike → ~~text~~（starter-kit 自带，转换支持但工具栏不暴露）

❌ 不支持（降级为纯文本）：
   code, codeBlock, image, table, taskList 等
```

### 5.4 Next.js App Router 兼容性

| 风险 | 说明 | 解决方案 |
|------|------|---------|
| Server Component 中无法使用 TipTap | TipTap 必须是 Client Component | 编辑器组件加 `"use client"`，通过 `next/dynamic` 在 Server Component 中引用 |
| Server Actions 需要在 Client Component 中调用 | P1.4 的 /plant 页面需要同时使用 Editor 和 Server Actions | /plant 页面是 Client Component，可以直接 `import` Server Actions |
| Turbopack 兼容性 | Next.js 16 使用 Turbopack，部分包可能不兼容 | `@tiptap/react` 和 `@tiptap/starter-kit` 在 TipTap v2.x 中已验证兼容 Turbopack |

### 5.5 TipTap 与 Framer Motion 共存

| 风险 | 说明 | 解决方案 |
|------|------|---------|
| 编辑器在 AnimatePresence 内部 | 路由切换时编辑器的 exit/enter 动画可能导致内容丢失 | 保存编辑器状态到父组件 state，避免依赖 DOM 持久化 |
| ProseMirror 的 DOM 操作与 Framer Motion 冲突 | 两者都操作 DOM，可能产生竞态 | 不在编辑器内部的元素上使用 Framer Motion 动画。编辑器本身是稳定的，不参与路由切换动画 |

### 5.6 新增依赖

| 依赖 | 是否允许 | 理由 |
|------|:--:|------|
| `@tiptap/react` | ✅ | 架构选型已定（ARCHITECTURE.md），是编辑器核心 |
| `@tiptap/starter-kit` | ✅ | 替代 10+ 个单独扩展包，减少依赖碎片 |
| `tiptap-markdown` 等社区包 | ❌ 不使用 | 自写简单转换器处理 7 种节点即可 |
| 拼音相关包 | ❌ 禁止 | P1.1 已确定 slug 方案 |

**本次新增依赖**：2 个（`@tiptap/react` + `@tiptap/starter-kit`）

## 七、最终建议

1. **立即实施**：安装 `@tiptap/react` + `@tiptap/starter-kit`，创建 Editor 组件
2. **同步开发**：`src/lib/markdown.ts` 中的 `jsonToMarkdown()` 转换函数

5. **验收重点**：中文输入法兼容性 + 7 种格式切换 + JSON ↔ Markdown 往返一致性
